# 記帳本

參考「記帳城市」的**記帳**部分做成的個人記帳 PWA（不含蓋房子／城市經營）。
純前端、無後端、無框架、無 npm 依賴 —— 資料存在瀏覽器的 IndexedDB，可自行同步到雲端硬碟。

- **Windows PC**：用瀏覽器開網頁版
- **Android**：一樣開網頁，Chrome 選單 →「加到主畫面」就變成全螢幕 App（不需要 .apk）
- **資料同步**：Google 雲端硬碟（手機＋電腦都可用），或指定一個 OneDrive／Google Drive 桌面版的同步資料夾

**線上版**：<https://sandtrace2794.github.io/Bookkeeping/>

---

## 功能

| 分頁 | 內容 |
|---|---|
| 總覽 | 本月支出、預算進度條、收入／損益／日均支出／連續記帳天數、**雲端同步卡**（一鍵連結或同步）、常用類別快速記帳、今日明細、本月支出排行 |
| 明細 | 依月份瀏覽，按日分組並顯示每日小計；可搜尋備註與類別（搜尋時跨全部月份） |
| 統計 | 可選**一個月／一年／自訂區間**；損益、支出類別圓餅圖、各類別金額條列、與上一期比較 |
| 設定 | 預算、幣別、每月起算日、深淺色主題、雲端同步、類別管理、匯出匯入、清除資料 |

### 記帳

預設 11 個類別：食物、飲品、交通、娛樂、居家、收入、3C、醫藥、消費、寵物、其他。都可以改名、換圖示顏色、調順序或刪掉。

- **收支別由類別決定** —— 只有「收入」算收入，其餘都是支出。記帳時不必先選收支，選類別就好；金額是收入時會顯示成綠色。自訂類別可在編輯時勾「算成收入」。
- **計算機鍵盤保留算式** —— 輸入 `120 + 45 + 30` 按 ✓ 得到 195，算式會跟著紀錄一起存下來，明細列與 CSV 都看得到，重新打開該筆也會顯示。
- **備註快填** —— 備註欄下方是用過的備註，最近一次標「上次」，其餘依使用次數排序；同類別沒用過備註時退回全域常用。
- **就地新增類別** —— 類別列最後有一格「＋ 新增」，在記帳面板就能開編輯器建類別，存好會自動選起來接著記這一筆，不必先跑一趟設定頁。
- **只能記過去** —— 日期最多到今天，不能新增未來的消費紀錄。
- 電腦版可直接用實體鍵盤輸入數字、`+` `-`、`Backspace`、`Enter`。

### 統計區間

月與年一律是**完整單位**：9/14 打開「一個月」看到的是整個 9 月，不是 8/14～9/14。「自訂」則自己指定起訖日。

報告順序：

1. **損益** —— 收入減掉所有支出，另附收入、支出、儲蓄率
2. **支出類別佔比** —— 圓餅圖，只放支出
3. **各類別金額** —— 條列，含收入
4. **與上一期比較** —— 本期 vs 上一個等長區間的總支出增減，以及變化最大的類別（上期 → 本期、差額）。支出變多是紅色、變少是綠色

上一期是自動對應的：一個月比上個月、一年比去年、自訂區間比緊鄰在前的同樣天數。

## 一、在 Windows PC 上開啟

需要 Node.js（`node -v` 有輸出即可）。在專案資料夾按兩下 **`start-windows.cmd`**，或手動執行：

```bash
npx --yes serve -l 5173 .
```

然後開啟 <http://localhost:5173>。

> 不要直接用 `file://` 開 index.html —— ES modules 與 Service Worker 都需要 http(s)。

---

## 二、在 Android 上開啟

Android 需要一個**公開的 https 網址**（Service Worker、「加到主畫面」、Google 登入都要求 secure context，同一個 Wi-Fi 的 `http://192.168.x.x` 不算）。免費部署到 GitHub Pages：

1. 在 GitHub 建一個 repo（Public 或 Private 都可以，Pages 對 Private repo 需付費方案，個人用建議 Public —— 裡面沒有任何帳號資料）。
2. 把這個資料夾的內容推上去：

   ```bash
   git init
   git add .
   git commit -m "記帳本"
   git branch -M main
   git remote add origin https://github.com/<你的帳號>/<repo>.git
   git push -u origin main
   ```

3. repo → **Settings → Pages → Source** 選 `Deploy from a branch`，branch 選 `main` / `(root)`，存檔。
4. 約一分鐘後網址會是 `https://<你的帳號>.github.io/<repo>/`。
5. 手機 Chrome 開這個網址 → 右上選單 →「加到主畫面 / 安裝應用程式」。

之後要更新就 `git push`，重開 App 即是新版（Service Worker 採「網路優先」，有網路時一定拿到最新檔案，離線時才用快取）。

> Cloudflare Pages、Netlify、Vercel 同樣可行，拖一個資料夾上去就好。

## 三、Google 雲端硬碟同步（手機＋電腦通用）

App 只會存取**自己建立的那一個檔案**（`bookkeeping.json`，使用 `drive.file` 權限範圍），看不到你雲端硬碟裡的其他東西。因為是純前端，需要你自己申請一組 OAuth Client ID（免費、一次性）：

1. 開 <https://console.cloud.google.com/> → 建立專案（名稱隨意）。
2. 左側 **API 和服務 → 程式庫** → 搜尋 **Google Drive API** → 啟用。
3. **API 和服務 → OAuth 同意畫面**
   - User Type 選「外部」→ 建立
   - 應用程式名稱、使用者支援電子郵件、開發人員聯絡資訊填自己的 Gmail → 儲存
   - 發布狀態維持「測試中」即可，在 **測試使用者** 加入自己的 Google 帳號
4. **API 和服務 → 憑證 → 建立憑證 → OAuth 用戶端 ID**
   - 應用程式類型：**網頁應用程式**
   - **已授權的 JavaScript 來源**（重點，兩個都加）：
     - `http://localhost:5173`
     - `https://sandtrace2794.github.io`  ← 只填到網域，不含路徑
   - 建立 → 複製 **用戶端 ID**（`xxxxx.apps.googleusercontent.com`）
5. 回到 App → **設定 → 雲端同步 → Client ID** 貼上 → 按 **連結帳號** → 授權。
6. 之後按 **立即同步**；勾選「變更後自動同步」則記帳後約 4 秒自動上傳。

手機和電腦填同一組 Client ID、登入同一個 Google 帳號，就會同步同一個檔案。

**同步規則**：雙向合併，以每筆紀錄的更新時間為準（last-write-wins）。刪除採「墓碑」標記而非真的移除，所以在 A 裝置刪掉的紀錄同步後也會在 B 裝置消失。不會因為某台裝置資料較舊而把新資料蓋掉。

**授權權杖只有一小時**，過期後要重按一次「連結帳號」（純前端 App 無法避免；不存 refresh token 反而比較安全）。因此**總覽頁最上面就有一張同步卡**，狀態分三種，一按就做對應的事：

| 卡片 | 狀態 | 按下去 |
|---|---|---|
| ☁️ 雲端同步 | 還沒填 Client ID | 跳到設定頁 |
| 🔑 需要重新連結 | 權杖過期或還沒授權 | 重新授權並立刻同步 |
| ✅ 已連結 | 權杖有效 | 立即同步 |

## 四、本機資料夾同步（電腦版替代方案）

如果你電腦已經裝了 OneDrive / Google Drive / Dropbox 桌面版：

**設定 → 雲端同步 → 本機資料夾 → 選擇資料夾**，挑一個在同步資料夾底下的目錄。App 會把 `bookkeeping.json` 寫進去，交給雲端軟體上傳；記帳後也會自動靜默寫檔。

僅電腦版 Chrome / Edge 支援（File System Access API），Android 請用上面的 Google 雲端硬碟方式。

## 五、備份與轉移

**設定 → 檔案備份**：

- **匯出 JSON** —— 完整快照（紀錄、類別、設定），可用來備份或搬到另一台裝置
- **匯入 JSON** —— 與現有資料**合併**（不是覆蓋），規則同上
- **匯出 CSV** —— 給 Excel / Google 試算表用，含 BOM 所以中文不會亂碼

## 檔案結構

```
index.html              版面（4 個分頁 + 記帳面板 + 彈窗）
manifest.webmanifest    PWA 設定（圖示、名稱、啟動方式）
sw.js                   Service Worker，離線快取（網路優先）
start-windows.cmd       Windows 一鍵啟動本機伺服器
css/app.css             全部樣式（深淺色主題用 CSS 變數）
js/
  app.js                介面控制：路由、記帳面板、各分頁渲染、設定
  store.js              應用狀態、記帳月計算、查詢彙總、匯入合併
  db.js                 IndexedDB 薄封裝（records + meta）
  sync.js               Google Drive / 本機資料夾 / 匯出匯入
  charts.js             純 SVG 環圈圖
icons/                  PWA 圖示（由 tools/make-icons.mjs 產生）
tools/make-icons.mjs    重新產生圖示：node tools/make-icons.mjs
```

沒有 build 步驟，改完檔案重新整理即可。

## 幾個設計上的取捨

- **記帳月起算日**：設成 5，則 3/5～4/4 都算「3 月」，薪水日不在月初的人比較好對帳。統計的「一年」也跟著記帳月走。
- **收支別不存在紀錄的 UI 上**：紀錄雖然有 `type` 欄位，但它完全由類別推導。改類別的「算成收入」時，該類別底下的既有紀錄會一起重新標記，不會出現同類別一半收入一半支出。
- **刪除不真的刪**：保留 `del: 1` 墓碑供同步用。設定頁的「資料」區會顯示有幾筆墓碑。
- **資料只存在瀏覽器**：清除瀏覽器網站資料會一併清掉，所以請設定雲端同步或定期匯出。
- **預設類別改版**：`store.js` 的 `CATS_VER` 加一之後，只有在「還沒有任何紀錄」時才會換成新的預設類別；已經開始記帳的話會保留自己調整過的類別。
